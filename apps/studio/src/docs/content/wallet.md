# 블록체인 사이트 — 지갑 로그인

메타마스크 같은 지갑으로 로그인하는 사이트(dApp)는 세 가지로 자동화합니다.

| 방법 | 언제 | 서명은 누가 |
|---|---|---|
| **사람의 크롬 + 사람 기다리기** | 사람이 옆에 있을 때 · 실제 지갑 | 사람이 메타마스크 창에서 직접 |
| **지갑 브라우저(MetaMask)** | 무인 실행 · 사이트가 MetaMask 확장을 직접 확인할 때(로그인 창에 «MetaMask Installed»가 떠야 하는 곳) | «MetaMask 승인» 동작이 진짜 MetaMask 화면을 누른다 |
| **테스트 지갑** | 무인 실행 · 테스트 Suite · QA 대역 · 사이트가 페이지의 지갑(window.ethereum)만 볼 때 | 서버가 테스트 지갑의 개인키로 |

어느 것인지 모르겠으면 사이트의 로그인 창을 보세요. MetaMask가 «Installed»로 뜨려면 진짜 확장이 있어야 하는 사이트이고, 그런 곳은 지갑 브라우저를 씁니다.

## 1. 사람의 크롬 + 사람 기다리기

1. 워크플로우 설정 › 브라우저를 **사람이 로그인한 크롬에 붙습니다**로 바꿉니다. 그 크롬에는 메타마스크가 깔려 있고 잠금이 풀려 있어야 합니다.
2. 녹화 중 사이트의 «지갑 연결»을 누르고 **🙋 사람 기다리기**를 넣습니다 — 로그인 화면의 표시는 «지갑 연결» 단추, 끝났다는 표시는 로그인 뒤에만 보이는 것(지갑 주소 · 내 정보).
3. 실행이 그 자리에서 기다리면 사람이 메타마스크 창에서 [연결] · [서명]을 누릅니다. 끝나면 저절로 이어 갑니다.

## 2. 지갑 브라우저(MetaMask)

진짜 MetaMask(13.0.0)를 실은 크롬을 **창을 띄워** 엽니다. 지갑마다 프로필 하나를 두고 계속 씁니다 — 처음 한 번 지갑을 준비하고(30초쯤), 다음부터는 잠금만 풉니다.

1. 워크플로우 설정 › **시크릿**에 «글자 하나» 종류로 시크릿을 만들고 테스트 지갑의 **개인키**(0x…64자리) 또는 **복구 문구**(12~24 단어)를 넣습니다.
2. 워크플로우 설정 › **브라우저**에서 **지갑 브라우저(MetaMask)**를 고르고, 아래 **MetaMask 지갑**에서 그 시크릿을 고릅니다.
3. **체인**(골라도 되고 비워도 됩니다) — 넣으면 페이지를 연 직후 처음 체인으로 맞춥니다(체인 id · 이름 · 화폐 기호 · RPC 주소). 사이트가 바꾸자고 하면 이 목록 안에서만 바꿉니다.
4. 웹페이지 노드에서 사이트의 «지갑 연결»(또는 «Connect»)을 누른 뒤에 **MetaMask 승인** 동작을 넣고, **끝났다는 표시**를 정합니다 — 로그인 뒤에만 보이는 것(지갑 주소 · 내 정보 · 사라지는 «Connect» 단추).

«MetaMask 승인»은 MetaMask 화면을 읽고 누를 만한 것만 누릅니다. 사이트 하나의 로그인이 화면 여러 개(연결 · 권한 · 서명)여도 끝 표시가 올 때까지 차례로 누릅니다.

| MetaMask 화면 | MetaMask 승인 |
|---|---|
| 연결 · 권한 | 누릅니다 |
| 로그인 서명(personal_sign · EIP-712) | 누릅니다 — 서명한 글을 노드 로그에 남깁니다 |
| 체인 추가 · 바꾸기 | 체인 목록 안이면 누릅니다 · 밖이면 멈춥니다 |
| 거래 · 토큰 승인 | «거래 허용»을 켠 체인만 — 아니면 멈춥니다. 점검(변경 감시)에서는 늘 멈춥니다 |
| 모르는 화면 | 누르지 않고 멈춥니다 |

- **화면이 있는 PC에서만 돕니다** — 창 없는 브라우저는 MetaMask 승인 창을 열지 않습니다. 데스크톱 앱이나 `--headed`로 켠 워커(사람 PC), 리눅스 서버라면 Xvfb 위에서 돌립니다. 그런 워커가 없으면 실행은 이유와 함께 바로 실패합니다.
- **MetaMask는 처음 쓸 때 그 PC가 받습니다**(GitHub · 약 24MB · SHA256 확인). 사내망에서 GitHub가 막혔으면 받아 둔 zip을 `FLOWSMITH_METAMASK_ZIP`로 줍니다.
- **Windows는 짧은 폴더에** — 지갑 프로필은 `%LOCALAPPDATA%\Flowsmith\w`에 둡니다. 경로가 길면 Windows 260자 제한에 걸려 MetaMask가 열리지 않습니다. 바꾸려면 `FLOWSMITH_WALLET_DIR`(예: `C:\fsw`)를 줍니다.
- 사이트가 사람의 확인(이메일 인증 코드 · Cloudflare)을 요구하면 그 앞에 **사람 기다리기**를 넣습니다. 한 번 풀면 프로필에 남아 다음부터는 건너뜁니다.
- 지갑에 그 사이트의 **계정이 있어야** 로그인 서명이 옵니다 — 계정이 없으면 사이트가 회원가입 화면으로 보냅니다.
- 같은 지갑으로는 한 번에 하나만 돕니다(같은 프로필을 두 크롬이 열 수 없습니다 — 차례를 기다립니다).

## 3. 테스트 지갑

페이지에 **테스트 지갑**을 넣고, 사이트가 부르는 계정 연결 · 서명 · 거래를 **서버가 개인키로** 처리합니다. 메타마스크 창이 없으니 빠르고 메타마스크가 바뀌어도 깨지지 않습니다.

1. 워크플로우 설정 › **시크릿**에 «글자 하나» 종류로 시크릿을 만들고(예: `qa_wallet`) 테스트 지갑의 **개인키**(0x…64자리)를 넣습니다.
2. 워크플로우 설정 › **테스트 지갑**을 켜고 그 시크릿을 고릅니다.
3. **체인** — QA 대역의 체인 id · RPC 주소를 적습니다. 사이트가 다른 체인으로 바꾸자고 하면 이 목록 안에서만 바꿉니다.
4. **거래 허용** — QA 체인에서 구매 · 등록처럼 거래가 필요하면 켭니다. 끈 체인의 거래는 거절됩니다.
5. **사이트에 보이는 이름** — «MetaMask»면 사이트가 메타마스크로 봅니다(isMetaMask · EIP-6963 io.metamask).

녹화할 때도 같은 지갑이 들어가 있으니 «지갑 연결»을 눌러 로그인하며 녹화하면 됩니다.

| 사이트의 요청 | 테스트 지갑 |
|---|---|
| 계정 연결 · 계정 묻기 · 체인 묻기 | 늘 답합니다 |
| 로그인 서명(personal_sign) · 구조화 서명(EIP-712) | 늘 서명합니다 |
| 체인 바꾸기 | 목록에 있는 체인만 |
| 거래 전송 | «거래 허용»을 켠 체인만 — 점검(변경 감시)은 보내지 않습니다 |
| eth_sign(아무 해시나 서명) | 늘 거절 |
| 잔고 · 계약 읽기 | 그 체인의 RPC로 |

지갑이 한 일(연결 · 서명한 글 · 보낸 거래)은 실행 기록의 그 노드 로그에 남습니다. 개인키는 페이지에도 기록에도 나가지 않습니다.

★**테스트 지갑 · QA 대역 전용**입니다. 실제 자산이 든 지갑의 키를 넣지 마세요.
