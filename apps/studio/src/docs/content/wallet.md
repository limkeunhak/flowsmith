# 블록체인 사이트 — 지갑 로그인

메타마스크 같은 지갑으로 로그인하는 사이트(dApp)는 두 가지로 자동화합니다.

| 방법 | 언제 | 서명은 누가 |
|---|---|---|
| **사람의 크롬 + 사람 기다리기** | 사람이 옆에 있을 때 · 실제 지갑 | 사람이 메타마스크 창에서 직접 |
| **테스트 지갑** | 무인 실행 · 테스트 Suite · QA 대역 | 서버가 테스트 지갑의 개인키로 |

## 1. 사람의 크롬 + 사람 기다리기

1. 워크플로우 설정 › 브라우저를 **사람이 로그인한 크롬에 붙습니다**로 바꿉니다. 그 크롬에는 메타마스크가 깔려 있고 잠금이 풀려 있어야 합니다.
2. 녹화 중 사이트의 «지갑 연결»을 누르고 **🙋 사람 기다리기**를 넣습니다 — 로그인 화면의 표시는 «지갑 연결» 단추, 끝났다는 표시는 로그인 뒤에만 보이는 것(지갑 주소 · 내 정보).
3. 실행이 그 자리에서 기다리면 사람이 메타마스크 창에서 [연결] · [서명]을 누릅니다. 끝나면 저절로 이어 갑니다.

## 2. 테스트 지갑

페이지에 **테스트 지갑**을 넣고, 사이트가 부르는 계정 연결 · 서명 · 거래를 **서버가 개인키로** 처리합니다. 메타마스크 창이 없으니 빠르고 메타마스크가 바뀌어도 깨지지 않습니다.

1. 워크플로우 설정 › **시크릿**에 «글자 하나» 종류로 시크릿을 만들고(예: `qa_wallet`) 테스트 지갑의 **개인키**(0x…64자리)를 넣습니다.
2. 워크플로우 설정 › **테스트 지갑**을 켜고 그 시크릿을 고릅니다.
3. **체인** — QA 대역의 체인 id · RPC 주소를 적습니다. 사이트가 다른 체인으로 바꾸자고 하면 이 목록 안에서만 바꿉니다.
4. **거래 허용** — QA 체인에서 구매 · 등록처럼 거래가 필요하면 켭니다. 끈 체인의 거래는 거절됩니다.
5. **사이트에 보이는 이름** — «MetaMask»면 사이트가 메타마스크로 봅니다(isMetaMask · EIP-6963 io.metamask).

녹화할 때도 같은 지갑이 들어가 있으니 «지갑 연결»을 눌러 로그인하며 녹화하면 됩니다.

| 사이트의 요청 | 테스트 지갑 |
|---|---|
| 계정 연결 · 계정 묻기 · 체인 묻기 | 늘 답합니다 |
| 로그인 서명(personal_sign) · 구조화 서명(EIP-712) | 늘 서명합니다 |
| 체인 바꾸기 | 목록에 있는 체인만 |
| 거래 전송 | «거래 허용»을 켠 체인만 — 점검(변경 감시)은 보내지 않습니다 |
| eth_sign(아무 해시나 서명) | 늘 거절 |
| 잔고 · 계약 읽기 | 그 체인의 RPC로 |

지갑이 한 일(연결 · 서명한 글 · 보낸 거래)은 실행 기록의 그 노드 로그에 남습니다. 개인키는 페이지에도 기록에도 나가지 않습니다.

★**테스트 지갑 · QA 대역 전용**입니다. 실제 자산이 든 지갑의 키를 넣지 마세요.
