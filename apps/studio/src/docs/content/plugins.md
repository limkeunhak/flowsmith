# 확장 플러그인

확장 노드(예: 사내 주문 시스템 읽기 · 넣기)는 **플러그인 묶음(.fspkg)** 하나로 만들어 올립니다. 젠킨스의 플러그인처럼 서버를 다시 켜지 않고 설치 · 업데이트 · 되돌리기가 되고, 워커에는 서버가 저절로 나눠 줍니다.

| 할 일 | 어디서 | 누가 |
|---|---|---|
| 묶음 만들기 · 서명 | 개발 PC — `flowsmith-ext build` | 확장을 만드는 사람 |
| 올리기 · 켜기/끄기 · 버전 고르기 | 왼쪽 **확장** 화면 | 관리자 |
| 사내 저장소에서 받기 | **확장** › 사내 저장소 › 새 버전 확인 | 관리자 |
| 워크플로우에서 쓰기 | 노드 고르기 › 확장 | 편집자 |

## 올리기

1. 왼쪽 **확장** › **묶음 올리기(.fspkg)**에서 파일을 고릅니다.
2. 서버가 묶음의 모양 · 파일마다의 해시 · **서명**을 보고, 실제로 불러 본 뒤에야 켭니다. 하나라도 틀리면 받지 않고 까닭을 보여 줍니다.
3. 켜지면 바로 노드 고르기에 나옵니다. **새로 시작하는 실행부터** 그 버전을 쓰고, 이미 돌고 있던 실행은 시작할 때의 버전으로 끝까지 갑니다.

## 버전 바꾸기 · 되돌리기

- 올린 버전은 지우지 않고 남깁니다. 카드의 **버전**에서 고르면 바로 그 버전으로 바뀝니다(되돌리기).
- **끄기** — 잠시 쓰지 않습니다. 그 노드를 쓰는 실행은 «확장이 설치돼 있지 않습니다»로 멈춥니다.
- **지우기** — 그 노드를 쓰는 워크플로우가 있으면 지울 수 없습니다(먼저 끄거나 노드를 빼세요).
- 버전을 만들(게시할) 때 그때의 플러그인 버전을 적어 둡니다. 나중에 플러그인이 바뀌면 편집 화면 위에 **«확장이 바뀌었습니다»**가 뜹니다 — **점검 실행**으로 아직 잘 도는지 확인하세요.

## 서명

플러그인 코드는 **서버 권한으로** 돕니다. 그래서 기본은 사내 서명 키로 서명된 묶음만 받습니다.

1. 키를 만듭니다(한 번) — 비밀키(.key)는 만드는 쪽만 갖고, 공개키(.pub)의 한 줄을 서버에 줍니다.
   ```
   node packages/pack/src/main.ts keygen 사내배포 --out ~/keys
   ```
2. 서버의 믿는 키 파일에 그 줄을 넣고 `FLOWSMITH_PLUGIN_KEYS=/etc/flowsmith/plugin-keys`로 서버를 켭니다. 한 줄에 «이름 공개키» 하나, `#`은 설명입니다.
3. 빌드할 때 `--key ~/keys/사내배포.key`를 줍니다.

시험 서버처럼 서명 없이 받아야 하면 `FLOWSMITH_PLUGIN_SIGNING=off` — 화면에 경고가 계속 보입니다.

## 사내 저장소

묶음을 모아 둔 폴더를 사내 웹 서버(nginx 등)로 내주고, 그 폴더에서 `flowsmith-ext index`로 `index.json`을 만듭니다.

```
node packages/pack/src/main.ts index /srv/flowsmith-plugins
```

**확장** › 사내 저장소에 `https://repo.사내/flowsmith-plugins/index.json`을 넣고 **새 버전 확인**을 누르면 묶음마다 «새 버전 · 지금 쓰는 것»이 보이고, **업데이트**로 받습니다. 받은 묶음도 index의 해시 · 서명을 똑같이 봅니다. 서버를 켤 때 `FLOWSMITH_PLUGIN_SOURCE`로 기본 주소를 줄 수도 있습니다.

## 워커

워커는 붙을 때 서버에서 켜 둔 플러그인을 받아(해시 확인) 그 PC에 남겨 두고 싣습니다. 새 버전 · 끄기도 저절로 따라갑니다. 워커가 아직 받는 중이면 그 워커로 가는 실행은 잠시 기다리고, 그 확장이 없는 워커로는 보내지 않습니다. 워커 화면의 «확장»에서 각 PC가 실은 버전을 봅니다.

받아 두는 곳은 그 PC의 `~/.flowsmith/worker-plugins`(바꾸려면 `FLOWSMITH_WORKER_PLUGINS_DIR`)입니다.

## 확장 만들기

확장 폴더의 `package.json`에 `flowsmith` 칸을 둡니다.

```json
{
  "name": "@사내/ext-shop",
  "version": "1.2.0",
  "description": "사내 주문 시스템 읽기 · 넣기",
  "flowsmith": { "id": "shop", "name": "사내 주문 시스템", "main": "src/index.ts" }
}
```

- `main`은 `export const extensions: Extension[]`를 내는 파일입니다. 노드 id는 모두 `<id>.`로 시작합니다(예: `shop.order-read`).
- 의존성(npm 꾸러미)은 빌드할 때 JS 하나로 묶입니다 — 서버 · 워커에서 npm을 받지 않습니다. 엔진 · 코어 · Playwright만은 서버 · 워커의 것을 씁니다.
- 버전은 `package.json`의 `version`입니다. 같은 버전을 내용만 바꿔 다시 올리면 받지 않습니다 — 버전을 올리세요.

```
node packages/pack/src/main.ts build extensions/shop --key ~/keys/사내배포.key
→ extensions/shop/dist/shop-1.2.0.fspkg
```

`flowsmith-ext inspect x.fspkg --keys 믿는키파일`로 묶음 안(노드 · 서명)을 미리 봅니다.

## 서버에 고정된 확장

`FLOWSMITH_EXTENSIONS`로 실은 확장은 «서버에 고정»으로 보이고 화면에서 바꾸지 않습니다. 같은 노드 id의 플러그인은 받지 않으니, 플러그인으로 옮길 때는 환경변수에서 빼고 서버를 다시 켠 뒤 올리세요.
