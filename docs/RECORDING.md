# 녹화로 플로우 만들기 (PLAN §9 B3)

코드 없이 **웹페이지 노드를 녹화 · 편집해서** «한 사이트에서 읽고 → 다른 사이트에 넣는» 플로우를 만드는 안내다.
예는 주문 관리 화면에서 주문을 읽어 사내 주문 시스템에 넣는 일이다. 시험 사이트(`apps/testsite` — 계정 kim / p@ss ·
`/orders`의 주문번호 A-1001)에서 같은 순서를 그대로 해 볼 수 있다.

## 0. 준비 — 사람의 크롬에 붙기

보안 프로그램 · OTP처럼 사람이 직접 로그인해야 하는 사이트만 이 준비가 필요하다. 아니면 1로 간다
(서버가 띄운 브라우저에서 녹화하고, 로그인은 시크릿 · «사람 기다리기»로).

**① 크롬을 원격 디버깅으로 띄운다** (사람의 PC). 늘 쓰는 프로필과 다른 폴더를 준다.

```powershell
chrome.exe --remote-debugging-port=9222 --user-data-dir=C:\flowsmith-chrome
```

**② WSL에서 붙을 수 있게** — 크롬의 디버깅 포트는 127.0.0.1에만 열린다. 서버가 WSL에 있으면 Windows에서 포트를 하나 잇는다(관리자 PowerShell).

```powershell
netsh interface portproxy add v4tov4 listenaddress=0.0.0.0 listenport=9223 connectaddress=127.0.0.1 connectport=9222
# 다 쓰면: netsh interface portproxy delete v4tov4 listenaddress=0.0.0.0 listenport=9223
```

⚠️ 이 포트는 사람의 크롬 전체를 내놓는다. 방화벽 안에서만, 쓰고 나면 내린다.

**③ 서버를 CDP 주소와 함께 띄운다** (WSL).

```bash
export FLOWSMITH_MASTER_KEY_FILE=~/.flowsmith.key
export FLOWSMITH_CDP_URL=http://$(ip route show default | awk '{print $3}'):9223   # 같은 PC의 Windows면 http://127.0.0.1:9222
node packages/server/src/main.ts --port 4400 --data ./data
```

사내 서버에서 쓴다면 ②③ 대신 그 PC에 워커를 잇는다(가이드 «워커»).

**④ 크롬에서 직접** 두 사이트에 로그인해 둔다(보안 프로그램 · OTP는 사람이 지난다).

플로우 설정 → 브라우저 → **«사람의 브라우저에 붙기»**. 이 설정이면 녹화도 그 크롬에서 한다.

- 노드의 시작이 **«사람이 연 탭에서»**면 주소에 그 글자가 든 탭(가장 최근 것)에 붙는다. 주소를 옮기지 않는다.
  주소로 다시 가면 작업 중이던 화면이 날아가는 사이트는 이것을 쓴다.
- **«주소로 가서»**면 크롬에 탭을 하나 열고, 녹화가 끝나면 그 탭만 닫는다. 쿠키는 사람의 것을 그대로 쓴다.
- 사람의 탭 크기는 바꾸지 않는다. 녹화가 끝나면 페이지에 심은 레코더는 꺼진다(누르는 것이 그대로 간다).
- 크롬 창에서 직접 눌러도 되고 Studio 오른쪽 화면에서 눌러도 된다. 둘 다 녹화된다.

## 1. 노드를 나눈다

화면 묶음마다 웹페이지 노드 하나를 둔다. 대략 이렇다.

| 노드 | 시작 | 하는 일 |
|---|---|---|
| 관리자 화면 · 주문 찾기 | 사람이 연 탭에서 (`관리자 화면 주소 일부`) | 주문번호로 조회 → 그 주문번호의 행 고르기 → 상세 열기 |
| 관리자 화면 · 상세 읽기 | 앞 페이지에서 이어서 | 주문번호 **확인** → 값 읽기 → 품목 표 → 배송 정보 팝업 읽고 닫기 |
| 주문 시스템 · 주문 넣기 | 사람이 연 탭에서 (`주문 시스템 주소 일부`) | 값 넣기 · 고르기 · 체크 → 등록 → 결과 기다리기 → 읽기 |

실행 입력에 `orderNo`를 정의한다. 플로우 설정의 **금지 버튼**에 `주문 취소|환불|삭제`처럼
절대 누르면 안 되는 단추의 글자를 넣는다. 녹화 중에도 실행 중에도 누르지 않는다.

## 2. 녹화하면서 할 일

| 화면에서 | 녹화가 하는 것 | 사람이 할 것 |
|---|---|---|
| 조회 결과 **표의 행**을 누른다 | 누르기로 남기고 «행 고르기» 제안을 붙인다 | 「표의 행 — 행 고르기로 남기기」를 켠다. 키 칸은 주문번호, 값은 `{{ $params.orderNo }}`. 막을 행: 상태 칸이 `취소`면 멈춤 |
| 누르면 **브라우저 확인창**(confirm)이 뜨는 단추(등록 · 삭제) | 라이브 화면에 확인창이 뜬다 — 답하면 그 누르기에 «확인창에 답하기»(문구 · 확인/취소)로 남는다 | 실행할 때 문구가 다르면 멈춘다. 늘 뜨는 창이 아니면 노드 설정에서 «답하지 않음»으로 |
| **체크 칸** | 직접 누르든 라벨을 누르든 바란 값(켜기/끄기)으로 남는다 | — |
| 누르기 뒤 **늦게 열리는 창** | «새 창으로 옮기기»로 남긴다(곧바로 열리면 누르기의 «새 창을 엽니다» · 확인창에 답한 뒤 열리면 그 누르기에) | 창을 여는 길이 경우마다 다르면(확인창이 더 뜸) 누르기의 «새 창을 엽니다»를 끄고 «새 창으로 옮기기»를 둔다 |
| **iframe 안**의 요소 | 프레임 경로를 이름(name)으로 먼저 잡는다 — 창 차례 id(`mdi_subWindow1_iframe`)는 연 화면 수에 따라 바뀐다 | — |
| 처음 한 번만 뜨는 **안내창**의 확인 | 떠 있는 창 안의 단추면 «있을 때만»으로 남긴다 | 늘 뜨는 창이면 끈다 |
| **팝업**을 여는 단추 | 새 창으로 옮겨 가 이어서 녹화한다 | 다 읽으면 창의 «닫기»를 누르거나 위쪽 «창 닫기» |
| 상세의 **주문번호** (읽기 모드) | 읽기로 남기고 지금 값을 같이 보여 준다 | 「읽지 말고 확인만」을 켜고 기대값을 `{{ $params.orderNo }}`로. 다른 건이 열려 있으면 멈춘다 |
| **고르기 칸**의 값 (읽기 모드) | «고른 보기의 이름»으로 읽는다(막힌 칸도 고를 수 있다) | — |
| **금액** (읽기 모드) | 글자로 읽는다 | 노드 설정에서 «바꾸기: 숫자로» (`12,500원` → 12500) |
| 표의 칸 (읽기 모드) | 표 전체로 읽기 제안 | 「표 전체로」를 켠다 |

녹화 뒤 노드 설정에서 더 정할 것:

- **조건이 맞을 때만** — 앞 노드에서 읽은 값에 따라 체크 · 라디오를 고를 때. 예: 선물 포장 체크는
  `{{ $input.giftWrap }}` 같다 `있음`일 때만, 「빠른 배송」 라디오는 `{{ $input.shipping }}` 같다 `빠른`일 때만.
- **기다리기 → 칸에 값이 찰 때까지** — 등록을 누른 뒤 결과 칸이 늦게 채워질 때.
- 넣는 값은 앞 노드의 출력(`{{ $input.orderNo }}`)이나 실행 입력으로 바꾼다. 녹화된 값은 그 순간의 값이다.

## 3. 확인

1. 노드마다 «녹화 → 이 노드의 동작을 먼저 재생하고 이어서 녹화»로 다시 열어 보면 재생이 끝까지 가는지 바로 보인다.
2. 「플로우 실행」에서 `orderNo`로 돌린다. 행 고르기 · 확인 · 막을 행이 일을 하는지 보려면
   취소된 주문번호(시험 사이트는 A-1002)로도 한 번 돌려 **멈추는지** 본다.
3. 게시한 뒤 «감시»로 주기 점검을 켜 두면 화면이 바뀔 때 알린다.

## 녹화가 하지 않는 것 — 사람이 메워야 하는 것

- **값 바꾸기(사이트 사이)** — 한 사이트의 「빠른 배송」을 다른 사이트가 다른 말 · 코드로 받으면, 그 사이에 값 다듬기나
  커스텀 노드를 두고 바꾸는 표를 적는다.
- **화면 상태 맞추기** — 녹화로는 사람이 한 순서 그대로만 한다. 남은 대화상자 · 다른 탭이 열린 채로 시작하면 멈춘다
  (그 대신 어디서 멈췄는지 알려 준다).
- **넣은 값 다시 대조** — 넣기는 칸마다 다시 읽어 확인하지만(blur 뒤 읽기), 결과를 읽은 값과 견주는 일은
  조건 · 검사 노드로 만든다.

이런 것이 많으면 그 노드만 확장 노드(코드)로 두는 것도 방법이다. 두 방식은 한 플로우에 섞을 수 있다.
