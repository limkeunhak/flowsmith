# Flowsmith — 개발 계획

> 웹 자동화 플로우 엔진. 웹 페이지에서 하는 일을 **노드**로, 노드 사이의 데이터 흐름을 **엣지**로
> 그린 비순환 그래프(DAG)를 만들고, 배포하고, 돌린다.
> 특정 업무를 모른다 — 사이트 · 화면 · 값은 플로우가 정하고, 엔진은 **선언형 웹 자동화의 틀**만 맡는다.

- 작성: 2026-10-14 · 이름: **Flowsmith** (한때 Page Relay였다 — 2026-10-15 다시 Flowsmith로)

---

## 2. 지키는 원칙

| 원칙 | Flowsmith |
|---|---|
| 클릭 dispatch 폴백 · 폴링 대기 · 모달 치우기가 한 곳에 | `engine`의 Primitives — 웹페이지 노드가 쓴다(커스텀 노드는 날 Playwright — 결정 4) |
| 유일한 검문소, 문제를 모아 한꺼번에 던진다 | `core`의 `parseFlow` — 매니페스트가 들어오는 유일한 문 |
| 순수, 브라우저 없이 시험 | `core`의 `compile` · `RunState` — 순서와 건너뛰기가 순수 함수 |
| 금지 버튼 | 플로우 설정의 **금지 버튼**. 웹페이지 노드의 모든 클릭이 통과해야 한다. ★커스텀 노드는 예외(결정 4) |
| 깨지면 멈춘다 · 못 찾으면 후보를 보인다 | 실행 실패 리포트 + 변경 감시 알림 |
| 마지막으로 맞다고 확인한 시각 | 동작마다 `verifiedAt` |
| 사람이 고른 요소에서 위치 짓기 | 레코더의 위치 후보 생성 출발점 |
| 개인정보 가림 · «잠글 수 없으면 안 적는다» | 시크릿 가림 · 마스터 키 없으면 서버가 안 뜬다 |
| 값 식은 치환만 | 표현식은 **치환만**. 로직은 커스텀 노드로 |

**하지 않는 것**: 특정 업무의 데이터 모델을 엔진에 두기, 사이트 · 화면을 SQL seed로 적는 방식.

## 3. 개념 모델

```
Flow (매니페스트, JSON — 버전마다 고정)
 ├─ params    실행할 때 받는 입력 (수동 실행 폼 · 웹훅 본문)
 ├─ nodes[]   { id, type, name, config }
 ├─ edges[]   { from: { node, port }, to: { node } }
 ├─ vars      플로우 전용 환경변수 (평문 · 화면에 보인다)
 ├─ secrets   플로우 전용 시크릿의 **이름과 종류만** (값은 따로 암호화해 둔다)
 └─ settings  금지 버튼 · 기본 타임아웃 · 감시 주기 · 점검용 입력값
```

### 3.1 노드와 포트

노드는 **입력 하나(객체)**를 받아 **출력 하나(객체)**를 낸다. 출력 포트는 노드 종류가 정한다.

| 종류 | 입력 | 출력 포트 | 출력 객체 |
|---|---|---|---|
| `web` 웹페이지 | `in` | `out` | `read` · `readTable` 동작이 이름 붙인 값들 |
| `condition` 조건 | `in` | 갈래마다 하나 + `else` | 받은 입력을 **그대로** 넘긴다 |
| `custom` 커스텀 | `in` | `out` | 사용자 코드가 돌려준 객체 |

### 3.2 실행 규칙

- 순서는 **위상 정렬**(같은 깊이면 노드 배열 순서). v1은 **한 번에 하나씩** 돈다 —
  한 실행 안의 웹페이지 노드들이 **브라우저 컨텍스트 하나**(쿠키 · 로그인)를 같이 쓰기 때문이다.
- 들어오는 엣지가 여럿이면(합류): 하나라도 값을 보냈으면 돌고, 전부 건너뛰었으면 건너뛴다.
  입력은 값을 보낸 엣지들의 객체를 **엣지 순서대로 얕게 합친** 것이다.
- 조건 노드가 고르지 않은 갈래 뒤쪽은 `skipped`. 갈래의 행동이 «종료»면 플로우가 그 상태로 끝난다.
- 노드 하나가 실패하면 플로우 전체가 실패한다(v1). 조용히 빠지지 않는다.

### 3.3 표현식 — 치환만

```
{{ $input.orderNo }}          이 노드의 입력
{{ $node.login.userName }}    앞선 노드의 출력 (★조상 노드만)
{{ $params.orderNo }}         실행 입력
{{ $vars.baseUrl }}           플로우 변수
{{ $secrets.shop.password }}  시크릿 (★넣기 동작에서만)
```

연산 · 함수 호출 · 조건식은 없다. 필요하면 커스텀 노드를 쓴다.

### 3.4 웹페이지 노드

```
start   { url } | { continue }       ← continue: 앞 웹페이지 노드가 머문 페이지에서 이어서
actions goto · click · fill · select · check · press · wait · read · readTable
```

노드 안에서 페이지가 넘어가도 된다(로그인 버튼 → 다음 페이지). 노드는 사용자가 정한 **일의 단위**다.

요소는 `Target`으로 기억한다:

```
Target
  label        사람 말 — "'로그인' 버튼"
  locators[]   후보 위치들. ★실행은 locators[0]만 쓴다 — 정확히 하나를 가리켜야 한다
  fingerprint  녹화 때의 지문(태그 · 주요 속성 · 글자 · 주변 글자) — 변경 감시에 쓴다
  frames[]     iframe 경로
  verifiedAt   마지막으로 맞다고 확인한 시각
```

동작마다 `risk: safe | unsafe`가 있다. 제출 · 저장처럼 되돌릴 수 없는 클릭은 `unsafe` —
**점검 실행은 unsafe 동작을 누르지 않는다**(§6).

### 3.5 조건 노드

```
cases[]  { id, label, match: all|any, rules[], then }   ← 위에서부터, 처음 맞는 갈래
else     { then }
rule     { left: 표현식, op, right?: 표현식 }
op       eq ne contains notContains startsWith endsWith matches
         empty notEmpty gt gte lt lte isTrue isFalse
then     { next } | { end: success|failure, message }
```

`next`인 갈래는 그 포트에서 나가는 엣지가 있어야 하고, `end`인 갈래는 없어야 한다.

### 3.6 커스텀 노드

```js
// 사용자가 쓰는 본문 — async 함수 몸통. input · page · ctx를 받는다
const total = await page.locator("#total").innerText();
return { total: Number(total.replace(/,/g, "")) * input.rate };
```

- `input`(객체)을 받아 객체를 돌려준다. `outputs[]`에 내보낼 이름을 적는다.
- `page`는 **날 Playwright `Page`**다(결정 4). `ctx`에는 `context`(BrowserContext) · `params` · `vars` · `log`.
  ★**금지 버튼 가드가 안 걸린다.** 커스텀 노드에서 무엇을 누르는지는 그 코드를 쓴 사람의 책임이다 —
  그래서 편집 화면에 «이 노드는 안전장치 밖에서 돈다»를 늘 보인다.
- 시크릿은 커스텀 노드에 넘기지 않는다(`$secrets`가 없다). 실행 결과 · 로그의 가림은 커스텀 노드 출력에도 똑같이 걸린다.
- `usesPage`가 true면 점검 실행이 그 노드 앞에서 멈춘다 — 무엇을 할지 미리 알 수 없다.
- `node:vm`에서 돌리고 타임아웃을 건다. ☆vm은 보안 경계가 아니다 — standalone에서는
  플로우를 만드는 사람을 믿는다. master/worker로 가면 격리를 다시 본다.

## 4. 아키텍처

```
flowsmith/  ← 디렉토리 이름은 그대로 · 패키지는 @flowsmith/*  (pnpm workspace · Node 24 · TypeScript, 빌드 없이 type stripping)
  packages/core      매니페스트 타입 · 검문소 · 컴파일(DAG · 순서) · 표현식 · RunState. 순수
  packages/engine    실행기 + Primitives(Playwright) + 노드 3종        ← 나중의 worker
  packages/recorder  주입 스크립트 · 위치/지문 짓기 · 녹화 → 동작
  packages/server    HTTP + WebSocket · 저장소 · 시크릿 · 스케줄러     ← 나중의 master
  apps/studio        React + @xyflow/react — 좌 플로우 / 우 라이브 페이지
  apps/testsite      로그인 · 폼 · 표 · 모달이 있는 시험 사이트
```

### 4.1 master/worker 경계

- server는 engine을 **`WorkerClient` 인터페이스로만** 부른다. standalone은 같은 프로세스 구현.
- 작업 단위 = `(플로우 버전 매니페스트, params, 이 실행에 쓰는 시크릿 값)`. 워커는 저장소를 모른다.

### 4.2 저장

- SQLite(`node:sqlite`). 플로우 버전은 **덮어쓰지 않고 쌓는다**. 배포 = «이 버전을 활성으로».
- 실행 기록: 노드별 상태 · 출력(가린 것) · 시간 · 실패 리포트.

### 4.3 라이브 패널 — A로 시작, B로 바꿀 수 있게

```
레코더 핵심 (표시 방식과 무관)          표시 방식 (갈아 끼운다)
  주입 스크립트: 이벤트 잡기 · 위치 짓기    A. screencast: 서버 Chromium → CDP 프레임 → 캔버스
  녹화 이벤트 → 동작 목록 변환              입력: 마우스/키 → Input.dispatch*, 한글은 insertText
  읽기 모드 · 시크릿 연결                   B. Electron: WebContentsView에 직접 — 같은 주입 스크립트
```

`LiveView` 인터페이스(열기 · 이동 · 녹화 시작/끝 · 이벤트 받기)를 두고, UI는 그것만 안다.
B로 바꿀 때 레코더 핵심과 UI는 그대로 두고 표시 방식 하나만 새로 쓴다.

## 5. 레코더

1. 노드에서 [녹화 시작] → 우측에 페이지. 클릭 · 입력 · 선택을 잡는다. 연속 입력은 마지막 값 하나로.
2. **읽기 모드**: 요소를 누르면 «이 값을 무엇이라 부를까요?» → 그 이름이 출력이 된다.
   표는 행 하나를 누르면 같은 모양의 행들을 찾아 `readTable`.
3. `input[type=password]`에 넣은 값은 **녹화본에 안 남는다** — «어느 시크릿에 넣을까요?»를 묻는다.
4. [녹화 끝] → 동작을 사람 말로 보인다(«'로그인' 버튼 누르기»). 순서 바꾸기 · 지우기 ·
   값을 변수/입력으로 바꾸기 · `unsafe` 표시.
5. 금지 버튼에 걸리는 클릭은 녹화 시점에 알린다.
6. ★위치를 지으면 **녹화 그 자리에서 Playwright로 되찾아 정확히 하나인지** 확인한다. 아니면 다음 후보로.
   사람 눈의 글자와 접근성 이름이 다르다 — `<label>기간 <select>…</select></label>`의 이름은
   「기간」이 아니라 「기간 1개월」이다(M1 시험에서 실제로 걸렸다).

## 6. 변경 감시

- **수동**: 실제 실행이 실패하면 그 노드 · 동작에 «깨짐» 표시.
- **주기**: 플로우별 주기마다 **점검 실행** — 점검용 입력값으로 페이지를 따라가며 각 요소를
  지문과 대조해 `ok · 바뀜 · 없음 · 여러 개`. ★unsafe 동작은 누르지 않고 «있는지»만 보고 멈춘다.
- **알림(v1)**: 플로우 화면 위 배너 + 노드 배지. 배지 → «녹화 때 요소 / 지금 요소» 차이 + [다시 지정].
  ★고치는 건 사람이다(결정 3).

## 7. 변수와 시크릿

| 참고 | 방식 |
|---|---|
| n8n | Credential을 별도 엔티티로, `N8N_ENCRYPTION_KEY`로 암호화. 노드는 ID로만 참조. 저장 뒤 값을 안 돌려준다 |
| Jenkins | credential ID 참조 · 콘솔 로그 자동 마스킹 |
| Airflow | Variables / Connections · Fernet 암호화 · 민감 키 로그 마스킹 · secrets backend 교체 |

- 플로우마다 `vars`(평문)와 `secrets`(쓰기 전용). 종류: `text` · `login { username, password, extra }`.
- AES-256-GCM. 마스터 키는 환경변수/키 파일. **키가 없으면 서버가 안 뜬다.**
- 저장한 값은 API로 **돌려주지 않는다** — 나가는 것은 «있다/없다»와 저장 시각뿐.
- 실행기는 이번에 쓴 시크릿 값을 알고 있으므로 로그 · 결과 · 실패 덤프에서 찾아 `***`로 바꾼다.
- 시크릿은 `fill` · `select`에서만 쓴다. 출력 · 커스텀 노드로는 안 간다.
- `SecretStore` 인터페이스 — 나중에 Vault나 master 쪽 저장소로 바꾼다.

## 9. B안 — 사용자가 녹화 · 편집으로 직접 만든다 (2026-10-15)

## 15. 알림 · HTTP 요청 (2026-10-16)

다른 시스템과 잇는 두 길 — **알림**(무슨 일이 생기면 사람에게)과 **HTTP 요청 노드**(플로우 안에서 API를 부른다). 자세한 것은 [ARCHITECTURE.md](ARCHITECTURE.md) §4.2 · §5.5.
정한 것:
- 알림은 **게시된 버전**의 실행 · 점검만 — 초안 시험마다 울리면 아무도 안 본다. 다른 플로우가 부른 실행은 부른 쪽이 알린다.
- 실패 · 사이트 바뀜이 이어지면 **처음 한 번만**(기본) — 5분마다 도는 일정이 5분마다 울리지 않게. 회복도 알릴 수 있다.
- 알림 주소는 `$vars` · `$secrets`만 — 실행마다 바뀌면 안 되고, Slack · Teams 주소는 그 자체가 열쇠라 시크릿을 권한다. 보낸 기록에 주소를 남기지 않는다.
- 메일(SMTP)은 아직 — 웹훅(JSON)을 메일 · 문자 서비스에 잇는다.
- HTTP 요청의 다시 해 보기는 **GET · HEAD만**(운영 원칙 «되돌릴 수 있는 것만»). 점검도 GET · HEAD만 보내고 그 밖의 요청 앞에서 멈춘다.
- JSON 본문은 JSON으로 먼저 읽고 글자 값 안에서만 채운다(값의 따옴표가 본문을 깨지 않게). 값 하나뿐인 글자는 값 그대로(숫자 · 목록 · 객체).
- 시크릿은 헤더 · 쿼리 · 본문에만 — 주소는 로그에 남는다. 헤더 값에 한글은 못 넣는다(HTTP 규칙) — 쿼리 · 본문으로.

## 16. 비개발자 사용성 1 — 값 칩 · 값 다듬기 (2026-10-16)

기획 정리(«비개발자도 쓴다»)의 P0 첫 묶음. 비개발자가 막히는 두 곳 — **표현식을 읽고 써야 한다** · **값을 다듬으려면 코드를 써야 한다** — 을 없앤다.
정한 것:
- 매니페스트는 그대로(표현식). **화면만** 사람 말로 보인다 — 칩 · 동작 문장. 표현식 그대로 보기는 「{ }」(고급 보기)로 남긴다(개발자 · 복붙).
- 칩의 이름은 그 값을 **만든 노드**의 이름으로(조건 노드는 건너뛴다). 닿지 않는 참조는 빨간 칩 — 검문소와 같은 판정.
- 값 다듬기는 core의 순수 함수(`applyTransform`) — 실행과 편집 화면의 미리 보기가 **같은 함수**라 미리 본 대로 돈다.
- 못 읽은 값(숫자 · 날짜)은 **지어내지 않는다** — 숫자는 비우고 날짜는 그대로 두고, 몇 개였는지 기록에 남긴다. 숫자로 견줄 수 없으면 거르기는 **멈춘다**(조용히 빠지면 틀린 목록 — 결정 3과 같은 생각).
- 글자 · 숫자 목록은 행마다 `{ 값 }`으로 본다. 객체 하나는 한 행짜리 목록. 내보내는 것: rows · count · first.
- 커스텀 노드는 «개발자용»으로 노드 고르기의 끝에 둔다.

## 17. 비개발자 사용성 2 — 결과 표 · 엑셀 · 메일 (2026-10-16)

실무자가 결과를 «받아 보는» 길. 개발자가 아니면 JSON을 읽지 않고, 결과는 엑셀과 메일로 받는다.
정한 것:
- 엑셀(.xlsx)은 **라이브러리 없이** core에서 만든다(시트 XML + 압축 없는 ZIP) — 브라우저(엑셀로 받기) · 서버(파일 변환 · 메일 첨부)가 같은 함수를 쓴다. 값은 바꾸지 않는다: 숫자는 숫자, 「00123」은 글자로.
- 표로 보이는 것은 **출력 중 목록인 칸** — 목록마다 표(시트) 한 장. 목록이 없으면 JSON 그대로.
- 파일은 바꾸지 않는다 — «엑셀»은 내려받을 때 바꿔 보내기만 한다(50MB까지).
- 메일 서버(SMTP)는 **서버 설정** — 플로우마다 정하지 않는다(비밀번호가 플로우에 들어가지 않게). 플로우의 알림 규칙은 받는 사람만.
- 결과 첨부는 **성공한 실행만** — 실패한 실행의 반쯤 모은 목록을 결과처럼 보내지 않는다.
- 이번 대화에서 메일 채널은 nodemailer로 작은 SMTP 서버까지 시험했다. **진짜 메일 서버(사내 · Gmail 등)로는 아직 보내 보지 않았다.**

## 18. 비개발자 사용성 3 — 템플릿 · 다음 할 일 (2026-10-16)

빈 캔버스에서 막히지 않게. 첫 화면에서 하고 싶은 일을 고르고, 편집 화면에서는 남은 일을 차례로 안내한다.
정한 것:
- 템플릿은 **뼈대** — 웹페이지 동작은 비워 두고 녹화로 채운다(사이트마다 다르다). 칸 이름을 모르는 채로 짐작하지 않는다(겹침 빼기는 «행 전체가 같은 것»만, 파일 쓰기의 겹침 기준은 비워 둔다).
- 템플릿 셋: 매일 목록 모아 메일로(일정 · 날짜별 파일 · 엑셀 첨부 메일) · 값 읽어 엑셀로 쌓기(`{{ $input }}` 한 행) · 모은 목록의 행마다 입력(«한 건» 플로우를 따로 만들고 행마다 부른다 — 결정 5). ★직접 파일 올리기는 하지 않는다 — 목록은 다른 플로우가 모은 파일에서만.
- «다음 할 일»은 **저장하지 않는다** — 언제나 초안 · 실행 기록 · 게시 상태에서 계산한다(템플릿이든 빈 플로우든 같다). 다 하면 사라진다. 숨기기는 이 브라우저에만 기억.
- 플로우 id는 사람이 짓지 않는다 — `템플릿-xxxx` 무작위(«id 직접 정하기»는 고급).
- `{{ $input }}`(앞 단계 전부)을 표현식에 더했다 — 치환만 한다는 원칙은 그대로(새 연산이 아니라 참조 하나).

## 19. 비개발자 사용성 4 — 깨졌을 때 고치는 길 (2026-10-17)

사이트가 바뀌어 플로우가 멈추면, 알림 → 링크 → 실패 카드 → 고치는 단추 → 게시가 끊기지 않게 잇는다.
정한 것:
- ★고치는 것은 **사람**이다(결정 3 그대로). 단추는 그 자리로 데려가기만 한다 — [다시 지정]은 녹화를 열고, [이 위치로 바꾸기]는 **지금 정확히 하나를 가리키는 후보**에만 보이며 누르기 전에는 아무것도 바뀌지 않는다.
- 실패 문구는 «무엇이 · 왜 · 무엇을 해 주세요» — 사이트 탓(못 찾음 · 여러 개 · 값이 안 남음 → 다시 지정), 입력 탓(고르면 안 되는 행 · 기대한 건이 아님 → 입력값 확인), 느림(시간 초과 → 다시 해 보기). «못 찾음»은 입력값이 틀려도 생긴다고 함께 적는다(확인 점검이 가려 준다).
- 게시된 버전에서 실패했는데 초안에서 그 동작을 지웠으면 단추는 고치지 않고 노드를 연다.
- 알림에 «고치려면» 한 줄 — 실패 카드의 단추와 같은 말. 사이트 바뀜 알림의 링크는 변경 감시 서랍을 연다.
- 고친 뒤 «다음 할 일»은 «고친 것을 새 버전으로 게시하기 — 지금 도는 것은 vN» — 초안만 고치고 게시를 잊으면 일정은 옛 버전으로 계속 깨진다.

## 20. 디자인 — n8n의 틀 · 파랑 (2026-10-17)

## 21. 노드 창 — 입력 | 설정 | 출력 · 단계 실행 (2026-10-17)

n8n의 노드 화면처럼, 노드를 누르면 캔버스 위에 세 칸이 열린다 — 왼쪽 **받은 값**, 가운데 **설정**, 오른쪽 **내놓은 값**. 비개발자가 «이 노드가 무엇을 받아 무엇을 내놓나»를 한눈에 본다.
정한 것:
- 단계 실행은 **초안만** — «앞 단계까지 실행»(stopBefore: 이 노드 앞에서 멈춘다)과 «이 단계까지 실행»(stopAfter: 이 노드까지 돌리고 멈춘다). 실행 기록에는 «초안 · 일부»로 남고, 알림은 울리지 않는다(초안이다).
- ★단계 실행도 실제 사이트에서 실제로 일어난다 — 되돌릴 수 없는 동작이 있는 웹 노드면 돌리기 전에 묻는다.
- 실행 입력은 마지막으로 «플로우 실행»에 넣은 값(이 브라우저) · 없으면 점검용 입력값.
- 가운데 칸은 옛 서랍과 같은 자리 이름(.drawer)을 쓴다 — 녹화 · 다시 지정 · 화면 시험이 같은 곳을 찾는다. Esc는 글자를 넣던 중에도 창을 닫는다(창이 캔버스를 덮는다).

## 22. 디자인 3 — 실행 중 · 노드 고르기 · 아이콘 · 빈 캔버스 (2026-10-17)

- 실행 중인 노드는 n8n처럼 **테두리를 따라 빛이 돈다**(파랑). 움직임을 줄이도록 설정한 사람(prefers-reduced-motion)에게는 돌지 않는다.
- 노드 고르기는 **무리로** — 웹에서 · 값과 파일 · 흐름 · 다른 시스템(확장 포함) · 고급(코드). 찾는 말을 넣으면 무리 없이 맞는 것만.
- 노드 아이콘은 **두 겹**(연한 면 + 선) — 종류 색이 타일 · 고르기 · 노드 창에서 같다. 노드 종류의 얼굴은 `editor/nodeMeta.tsx` 한 곳.
- 빈 캔버스는 «첫 단계 더하기» + «보통은 웹페이지로 시작» + «템플릿에서 시작하기». «다음 할 일»도 빈 플로우에서는 «첫 단계 더하기»가 먼저다.

## 23. 디자인 4 — 실행 기록 · 첫 화면 목록 · 좁은 화면 (2026-10-17)

- **실행 기록**은 n8n처럼 — 왼쪽 목록을 상태(전체 · 성공 · 실패 · 멈춤) · 실행 방법으로 거르고 날짜별(오늘 · 어제 · 날짜)로 묶는다. 실패는 한 줄 까닭까지. 오른쪽 위에 **그 실행의 캔버스**(읽기 전용, 노드마다 성공 · 실패 · 안 돎), 아래에 로그. 캔버스의 노드를 누르면 로그가 그 노드로 간다.
  캔버스는 그 실행이 쓴 **버전**으로 그린다(GET /api/flows/:id/versions/:v). 초안 실행이면 지금 초안으로 그리고 «그때와 다를 수 있다»고 적는다.
- **첫 화면 목록** — 행마다 쓰인 노드 아이콘(최대 4) · 켜 둔 일정(사람 말) · 마지막 실행(성공/실패 · 언제). 거르기: 전체 · 게시됨 · 할 일 있음 · 실패 · 바뀜. 서버의 목록 응답에 `nodeTypes` · `schedules` · `lastRun`을 더했다.
- **좁은 화면** — 960px 아래: 사이드바는 아이콘만, 서랍은 캔버스 위로 뜬다, 실행 기록은 위아래로. 640px 아래: 위 막대가 두 줄(이름 · 게시 / 편집기 · 실행 기록), «다음 할 일»은 접혀서 시작, 템플릿은 한 줄에 하나.
- 조건 노드가 실패로 끝낸 실행에는 «실패한 노드를 고르세요» 대신 «조건 노드가 실패로 끝냈습니다»라고 적는다.

## 24. 사내 서버형 1 — 로그인 · 권한 (2026-10-17)

배포는 **사내 서버형**으로 정했다(사람마다 설치하지 않고, 서버 한 대를 브라우저로 함께 쓴다). 로그인 서버(사내 SSO)는 나중에 잇는다.
정한 것:
- **누구인가와 무엇을 해도 되나를 나눈다.** 역할 · 권한 · 세션 · 감사 기록은 지금 다 만든다. 로그인은 임시(메일 + 비밀번호)이고, 바깥 로그인을 이을 자리는 `Auth.signIn({ email, name })` 하나다 — 처음 온 사람은 «보는 사람», 관리자가 역할을 준다.
- 역할 넷: 관리자 · 편집자 · 실행자 · 보는 사람. 실행자는 **게시된 버전만** 돌린다(초안 시험 · 단계 실행은 편집자).
- 권한은 `needOf` 한 곳 — 새 길을 더하고 빠뜨려도 기본이 편집자(닫힌 쪽). 화면은 단추를 감출 뿐, 막는 것은 서버다.
- **HOST를 밖으로 열면 로그인은 끌 수 없다** — 로그인 없이 열면 누구나 플로우를 돌리고 서버에서 코드를 돌린다. 이 PC(127.0.0.1)에서는 지금처럼 혼자 쓴다.
- 첫 관리자는 콘솔의 **설정 토큰**으로만 — 먼저 접속한 아무나 관리자가 되지 않게.
- 밖으로 열 때 함께 닫는 것: HTTP 요청 · 알림이 서버 자기 자신 · 클라우드 메타데이터를 부르지 못하게(사내 주소는 둔다 — 사내 API를 부르려고 쓴다) · 원하면 커스텀 코드 끄기.
- 남은 것: 로그인 서버 잇기 · 팀별로 플로우 나누기 · master/worker(사람 PC의 크롬에 붙는 일은 그 PC에 워커가 필요하다).

## 25. 사내 서버형 2 — 팀 (2026-10-17)

- 팀은 관리자가 만들고 사람을 넣는다(한 사람이 여러 팀). **역할은 사람마다 하나**(팀마다 다르지 않다) — 단순하게 시작한다.
- 플로우는 한 팀에 속하거나 **공용**(팀 없음 — 모두가 본다). 지금 있던 플로우는 공용이다.
- 관리자가 아니면 내 팀 + 공용만. 남의 팀 것은 **403이 아니라 404** — 있다는 것도 알리지 않는다. 실행 · 점검 · 저장 파일 · 녹화 · 실행 화면 보기까지 같다.
- 플로우를 만들 때 · 옮길 때는 **내가 속한 팀**으로만(관리자는 어디든). 공용으로는 누구나.
- 다른 플로우 부르기 · 파일 읽기는 **공용이거나 같은 팀**만 — 공용 플로우는 공용만 부른다(공용은 모두가 보니, 공용을 통해 팀 것이 새지 않게).
- 플로우가 남아 있는 팀은 지우지 않는다.

## 26. 워커 — master/worker (2026-10-17)

사용자: «마스터 워커 모드랑 스탠드얼론이랑 둘 다» · «노드 확장 · 노드 관리 페이지 · 실행할 때 워커 지정 — 젠킨스처럼».

- **둘 다** — 워커를 붙이지 않으면 standalone(서버 안의 워커만). 붙이면 master/worker. 따로 켜는 «모드»는 없다.
- 이름은 화면에서 **«워커»** — 이 서비스에서 «노드»는 이미 플로우의 단계(웹페이지 노드 …)라 비개발자가 헷갈린다. 젠킨스의 노드 = 우리의 워커.
- 워커는 **사람 PC에 켜는 작은 프로그램**(packages/worker) — 브라우저로 Studio를 여는 것만으로는 워커가 아니다(웹 페이지는 그 PC의 크롬을 다룰 수 없다). 관리자가 «워커»에서 만들고 토큰을 준다.
- 연결은 **PC가 서버로**(WebSocket · 워커 토큰). 사내망 안쪽 PC에 서버가 들어갈 수 없다. 시크릿이 오가니 https 서버에만(시험은 예외 env).
- 어디서: 이번만(실행 단추 · API의 `on`) → 플로우 설정 → 서버. 워커 하나 · **라벨**(젠킨스의 label — 그 라벨의 비어 있는 워커).
- 자리 = 워커마다 동시 실행 수(기본 1 — 크롬 하나에 두 실행이 붙지 않게). 서버의 동시 한도는 서버 실행만 센다.
- **못 가면 기다리지 않고 바로 실패** — 젠킨스는 노드가 올 때까지 기다리지만, 일정이 조용히 쌓이면 아무도 모른다. 실패하면 알림이 간다. 자리가 찬 것(붙어는 있음)은 줄을 선다.
- **파일은 서버에** — 워커에서 돌아도 파일 노드는 서버의 파일 뿌리를 쓴다(엔진에 `FileOps`를 두고 워커는 서버에 맡긴다). 화면의 «저장 파일»이 그대로 보인다. 워커는 그 실행이 닿는 폴더만.
- 팀 전용 워커(그 팀 · 공용 플로우만) · 모든 팀용. 팀은 만들 때 정한다.
- 아직: 워커 실행의 화면 보기 · «누른 사람의 PC에서»(사람마다 내 워커). (attach 녹화는 §28에서 됨)

## 28. 녹화도 그 PC에서 (2026-10-17)

사용자: «녹화는 클라이언트에서 안 돼? 녹화는 플로우 만들 때만 쓰는데».

- 웹 페이지(Studio)만으로는 안 된다 — 브라우저는 보안상 같은 PC의 다른 크롬 탭을 다루지 못한다. 녹화는 그 크롬에 붙어(CDP) 스크립트를 심고, 녹화한 동작을 Playwright로 다시 눌러 확인하는 일이다.
- 그래서 **그 PC의 워커 프로그램**이 한다(§26의 같은 프로그램). 서버는 Studio(/api/live)와 워커 사이를 잇기만 한다 — 같은 RecorderSession, 같은 녹화 메시지.
- 사람은 **자기 크롬 창에서 직접** 해도 된다(Studio의 화면에서 해도 되고). Studio에는 녹화된 동작과 그 크롬의 화면이 온다.
- 필요한 것은 사람의 크롬에 붙는 플로우(attach — 보안 프로그램 · OTP 사이트)뿐. 브라우저를 띄우는 플로우는 서버에서 녹화해도 어느 PC에서나 된다.
- 어느 PC: «녹화 시작»에서 고른다. **이 브라우저가 기억한다**(= 그 사람의 PC) — «다시 지정»처럼 폼을 거치지 않는 녹화도 그 PC로 간다.
- 녹화는 실행 자리를 쓰지 않고, **잠시 끈 워커에서도 된다** — 실행은 안 받고 녹화만 하는 PC. 팀이 맞아야 한다(앞 단계 재생에 쓰는 풀린 시크릿이 간다).
- 크롬 확장으로 하는 길은 접었다 — 녹화 확인 엔진(Playwright)을 확장 안에 다시 만들어야 한다.

## 32. 열린 API — 밖에서 조회 · 제어 (2026-10-17)

- 사용자: «이 서비스를 조회하거나 제어할 수 있는 API를 오픈하고 싶다. 사이드바에 API 섹션 · swagger 형식의 페이지에서 목록을 보고 호출해 보게».
- **명세는 길에서 만든다** — 따로 적은 YAML은 길과 어긋난다. 라우터가 패턴을 기억하고(`Route.pattern`), `http/docs.ts`(길마다 무리 · 요약 · 입력 · 예)와 `needOf`(필요한 역할)를 합쳐 OpenAPI 3.0을 만든다(`GET /api/openapi.json`, 로그인 없이 — 명세는 비밀이 아니다). 설명 없는 길 · 길 없는 설명은 시험(`drift`)이 잡는다.
- **API 토큰** — 사람마다(`api_token`, 해시만). 역할은 토큰과 그 사람의 **지금** 역할 중 낮은 쪽이라 사람의 역할을 내리거나 끄면 토큰도 따른다. 사용 기간은 1~365일 또는 없음. 쿠키가 아니라 머리글이라 다른 출처에서 와도 위조가 아니다 → 같은 출처 검사를 건너뛴다. CORS 머리글은 내지 않는다(다른 웹사이트의 브라우저 스크립트는 여전히 못 부른다 — 서버끼리 · 스크립트용).
- ★토큰으로는 토큰을 만들 수 없고 비밀번호도 못 바꾼다 — 새는 토큰이 스스로 늘거나 사람을 빼앗지 못하게. 토큰으로 한 일은 만든 사람의 메일로 기록된다(누가 했나는 그대로).
- 화면: 사이드바 «API» → `#/api`(Swagger UI — `swagger-ui-dist`, 이 화면을 열 때만 받는다 · deepLinking 끔(#은 앱이 쓴다) · «Try it out»은 지금 로그인 쿠키로) · `#/api/tokens`(내 토큰). 어둡게일 때는 Swagger를 통째로 뒤집는다(`--swagger-filter`). 앱의 전역 단추 · 칸 · 링크 모양은 Swagger 안으로 들이지 않는다(`:where(:not(.swagger-ui *))` — 세기는 그대로).
- `@scarf/scarf`(swagger-ui-dist의 사용 통계)는 설치 스크립트를 돌리지 않는다(pnpm-workspace.yaml).

## 33. 게시본 한 번에 (2026-10-17)

- `GET /api/flows/:id/published` — 밖이 게시된 버전을 **한 번에**, 안 바뀌었으면 **304**로. 전에는 플로우 → 그 버전 두 번 불러야 했고, 그 사이에 게시가 바뀌면 어긋날 수 있었다.
- ETag = uid + 버전(버전은 바뀌지 않으니 충분하다 · 되돌려 게시하면 바뀐다 · 같은 id로 다시 만든 플로우와 섞이지 않는다).
- ★«내려짐»(404 `reason: "not-deployed"`)과 «서버가 안 됨»을 가른다 — 서버가 잠깐 죽은 것이면 받아 둔 버전으로 일하고, 사람이 일부러 내린 것이면 받아 둔 버전도 쓰지 않는다. `HttpError`에 기계가 읽는 `reason`을 더했다(오류 본문 `{ error, problems?, reason? }`).
- 게시한 때 · 사람을 남긴다(`flow.deployed_at` · `deployed_by`, 내릴 때도) — 감사 기록 · 응답에 싣는다.

## 35. 사람 기다리기 — 로그인 · 본인 인증 (2026-10-17)

- 사용자: «플로우 실행 중간에 사용자 인증이 필요한 경우 — 로그인 화면이 뜨면 로그인을 기다리고(타임아웃) 정상이면 다음 동작이 이어져야. 다른 웹페이지 노드처럼 레코딩이 가능해야» ·
  정한 것: 서버 브라우저면 실행 화면으로 로그인(예) · 일정 · 웹훅으로 돌다 기다리면 알림(예).
- 새 웹 동작 `human` — `prompt`(안내) · `appears`(이 화면일 때만 — 없으면 건너뜀. 없고 끝 표시가 «사라지면»이면 그 요소를 화면으로 본다) ·
  `done`(사라지면 · 보이면 · 주소 — 처음부터 맞으면 기다리지 않는다) · `timeoutMs`(기본 5분 · 10초~30분). «있을 때만»(optional)은 같이 못 켠다(appears가 맡는다).
  전체 시간 제한이 기다리는 시간보다 짧으면 검문소가 막는다. 다시 해 보기는 하지 않는다.
- 엔진: 300ms마다 끝 표시를 본다(한 번에 오래 기다리지 않는다 — 멈추기 · 창 닫힘 · 로그인 중 페이지 이동을 바로 안다). 이벤트 `human`(waiting · done · timeout · stopped · failed).
  **사람이 화면을 만질 수 있을 때만** 기다린다(`RunOptions.human` — 사람의 크롬 · 레코더 페이지 · 서버의 실행 화면 · 창이 보이는 워커). 아니면 기다리지 않고 바로 멈춘다(아무도 로그인할 수 없다).
  점검 실행은 그 앞에서 멈춘다.
- 서버: 실행 화면(run-screens)이 **기다리는 동안만 · 실행자 이상**의 입력을 그 페이지로 넘긴다 — 평소에는 보기만(실행과 엉킨다). 입력은 남기지 않는다(비밀번호가 지나간다).
  알림 이벤트 `human` — 끝나기 전에 보낸다(게시된 버전 · 부른 실행도 — 누군가 로그인해야 부른 실행도 이어 간다).
- 녹화: «🙋 사람 기다리기» → ① 표시 고르기(읽기 모드 — 페이지에 안 감) → ② 직접 로그인(둘러보기 모드 — **녹화 안 됨**) → ③ 끝 표시. 다시 녹화할 때 재생이 이 동작에 오면 라이브 화면의 덮개를 걷고 사람이 로그인한다 —
  그래서 레코더 세션은 재생 **전에** 허브에 넘긴다(`RecorderSession.open`의 created — 전에는 준비가 끝난 뒤에야 넘겨 그동안의 입력이 버려졌다).
- 화면: 실행 로그 «사람을 기다리는 중 · 남은 시간» · 서버 브라우저면 실제 화면이 저절로 열린다 · 알림 링크로 연 실행 기록도 진행을 이어 받는다(지난 것부터).
- (2026-10-17 고침 — 사용자가 실제 사이트로 시험하다 «실행 화면이 멈춰 클릭이 안 된다») 두 번째 사람 기다리기가 **11ms 만에 끝나** 화면이 «보기만»으로 돌아갔다.
  끝 표시가 자리만 가리키는 CSS(`#banner > … > h3`)라, 인증 팝업 뒤에 이미 있던 앞 단계 제목을 «보인다»로 잡았다. 고침:
  ① «이 화면일 때만»의 요소(팝업)가 아직 보이면 끝나지 않았다 ② 끝 표시 · 화면 표시는 녹화 때 글자(앞 12자)도 맞아야 «그 요소» ③ 시간 초과 문장이 무엇이 안 맞았는지 말한다 ·
  «지금 주소가 되면»은 `#/…`(해시 라우터) 경로를 남긴다(버리면 어느 화면에서나 맞았다).

### 42-7. AI가 노드 속까지 — 1단계: 설명서 · 예 · 같은 사이트의 녹화 다시 쓰기 (2026-10-25)

사이트 화면을 AI 회사로 보내는 것은 **관리자 설정 · 기본 끔**(내 권고를 따름).

- 점검 실행으로 스스로 고치기는 ③으로 옮겼다 — 웹 동작이 빈 자리면 돌려 볼 것이 없다.

### 42-8. AI가 노드 속까지 — 2단계: AI가 사이트를 본다(보기만) (2026-10-25)

- 로그인 뒤 화면은 아직 못 본다(새 브라우저) — ③에서 AI가 직접 누르며(로그인은 시크릿 · 사람 기다리기).
- 시험: snapshot(로그인 화면 — 칸 · 단추가 하나로 가리키는 위치 · 그 위치로 실제로 누름 · 넣은 비밀번호는 없음 / 표 — 열 이름 · 행 위치 · 상태 글자) · server(켜기 전 403 · file:// 거절 · 요약 · 다시 보기 · 닫기) · agent(도구는 켰을 때만 · open_page → from p1~p3 → 위치가 들어감 · 다음 말로 넘김).

### 42-9. AI가 노드 속까지 — 3단계: 직접 해 보기 · 돌려 보고 스스로 고치기 (2026-10-25)

- **act**(POST /api/ai/browse/:id/act · AI 도구) — 연 화면에서 ref 요소를 누르기 · 넣기 · 고르기 · 키(엔진 Primitives — 녹화와 같은 길). 그 뒤 화면을 다시 요약해 돌려준다 → AI가 사람이 녹화하듯 동작 순서대로 해 보며 화면마다의 요소를 from으로 쓴다.
  - ★누르지 않는 단추는 **그 워크플로우의 금지 버튼**(설정 forbiddenLabels)이 정한다(409) — §42-11. AI가 만든 누르기 중 녹화기와 같은 낱말(저장 · 제출 · 결제 · 삭제 …)이 붙은 것은 «되돌릴 수 없음»으로 표시돼 점검 실행이 그 앞에서 멈춘다(녹화한 것과 같다).
  - ★시크릿 값은 AI가 모른다 — 넣을 값이 {{ $secrets.x.password }}면 **서버가 그 워크플로우의 시크릿으로 바꿔 넣는다**(볼 수 있는 사람만 · 응답 · 요약에 안 남음). 다른 표현식은 받지 않는다(실행 입력은 시험 값을). 새 워크플로우(시크릿 없음) · 본인 인증 · 캡차면 «사람 기다리기» + 빈 자리.
  - 다시 본 화면의 같은 요소(첫 위치가 같음)는 같은 ref를 쓴다 — 볼 때마다 번호가 늘지 않게.
- **try_flow**(POST /api/ai/try · AI 도구) — 받아들인 마지막 제안을 **점검 실행**(probe — 되돌릴 수 없는 동작 앞에서 멈춤 · 요소를 녹화 때와 견줌 · 서버의 새 브라우저 · 1분)으로 돌린다. 실패한 노드 · 못 찾은/달라진 요소 · 멈춘 곳을 말로 돌려주고(ai/agent.ts tryText) AI가 고쳐 다시 낸다. ★점검 실행은 못 찾아도 멈추지 않고 보고(probe broken)에 남긴다 — 둘 다 «고칠 것».
- 반복은 16번까지(보기 · 해 보기 · 돌려 보기가 더해져서) · «AI가 한 일»에 «눌렀습니다 «…»» · «점검 실행 — 통과/고칠 것».
- 시험: server(아이디 넣기 · 비밀번호는 시크릿으로 — 응답에 값이 없음 · 누르면 /home · {{ $params }}는 400 · «주문 취소»는 409 / 점검 실행 — 맞으면 성공 · probe ok, 틀린 요소면 broken과 그 요소) · agent(act로 넣고 누름 → 다음 화면의 요소 · 같은 요소는 같은 번호 · try_flow 실패 → 고쳐서 통과).

### 42-11. 누르지 않는 단추는 워크플로우가 정한다 (2026-10-25 · 사용자 결정)

  - 그대로 둔 것: 점검 실행(try_flow · probe)은 «되돌릴 수 없음»으로 표시된 누르기 앞에서 멈춘다 — 점검이라 그렇다(실행은 누른다).

- 시험: server(금지 버튼이면 409 · 정말 안 눌림 · 틀린 정규식 400 · 허용이면 눌림) · 대본 모델(금지 → 거절을 받고 못 한다고 답함 / 허용 → 눌러 보고 그 동작을 넣음).

사용자: «워크플로우가 너무 많아졌는데 정돈이 안 된다»(MSU QA 예시 72개를 올린 뒤). 본 것: 한 줄 71px라 한 화면에 9개 · 이름 앞에 «Navigator ·» 같은 앞말을 붙여 묶음을 흉내 내고 있었다 · 줄마다 같은 노드 아이콘 · «게시됨 v1» · 설명은 안 보임 · 72개가 다 게시돼 «게시됨» 거르기가 아무것도 거르지 않음 · 템플릿이 화면 여덟 장 아래.

## 46. 뒤로 · 앞으로 — 화면 둘러보기에서 고친 것 (2026-10-27)

사용자: «전체 페이지를 돌아보면서 어색한 부분 — 브라우저의 뒤로 · 앞으로를 포함해서». 본 것과 정한 것(권장 순서대로):
1. **저장하지 않은 고침이 소리 없이 사라졌다** — 확인은 «← 목록» 링크 · 창 닫기에만 있었고 뒤로 가기 · 위 메뉴로는 묻지 않고 떠났다(Suite 화면도). → `shell/nav.ts`: 해시가 바뀌는 세 길(링크 · 뒤로/앞으로 · `navigate`)이 모두 지킴이(`useLeaveGuard`)를 거친다. 머무르면 주소를 되돌린다(링크 · 뒤로는 이미 바뀐 뒤에 알게 되어 원래 주소를 다시 넣는다 — 앞으로 갈 기록은 그때 끊긴다. 고침을 잃는 것보다 낫다). 빈 워크플로우의 이름을 묻는 중에 떠나면 지운다(뒤로 가기로 빈 «새 워크플로우»가 쌓이던 것).
2. **뒤로 가기가 기대와 달랐다** — 화면을 덮는 작업 시트에서 뒤로 가면 편집 화면을 통째로 떠났고, 실행 기록 탭 · 고른 실행은 주소에 없었다. → 주소에 둔다: `#/flows/:id/nodes/:nodeId`(시트) · `/runs(/:runId)`(실행 기록). 시트는 처음 열 때만 기록을 쌓고 단계를 오가면 바꿔 쓴다(뒤로 한 번이면 캔버스) · 실행 고르기도 바꿔 쓴다 · 탭은 쌓는다. 편집 화면은 워크플로우가 바뀔 때만 새로 그린다(시트 · 탭 · 실행을 바꿔도 초안은 그대로 — 대신 같은 워크플로우 안에서는 서버의 초안을 다시 읽지 않는다).
3. **목록으로 돌아오면 처음부터** · **탭 제목이 늘 «Flowsmith»** → 목록은 찾던 말 · 거르기 · 스크롤을 이 탭에서 기억한다(sessionStorage) · 화면마다 «이름 · Flowsmith»(`shell/title.ts` — 이름을 아는 화면은 제 것을).
4. 작은 것 — 좁은 화면의 위 메뉴는 오른쪽 끝을 흐리게 하고 지금 길을 가운데로 · API · 가이드를 길 끝에(전엔 좁으면 감춰져 갈 수 없었다) · Suite 화면의 저장 · 전체 실행을 오른쪽 끝에 · 모르는 주소는 첫 화면인 척하지 않고 «없는 화면»(어느 길도 켜지 않는다).


## 47. 두 지갑 거래 — 지갑을 실행마다 · 새로고침하며 기다리기 (2026-10-27)

사용자: «거래소 시나리오 중에 두 브라우저에서 동시에 동작하는 시나리오가 있다 — 어떻게 구성할까»(msu-e2e-test 03 · 08 · 09 · 10). 본 것: 원본은 판매자 · 구매자 브라우저를 둘 다 띄워 두지만 **차례를 주고받는다**(역할 → 등록 · 승인 → 반영 → 정책 대기 → 구매 · 승인 → 정산 → 정리). 둘을 띄워 두는 까닭은 지갑 준비가 비싸서인데, 지갑 브라우저는 지갑마다 프로필이 남아 로그인이 이어진다.
정한 것 — **지휘 워크플로우 + 역할 워크플로우**(«다른 워크플로우 실행»으로 차례로 · 실패해도 이어 가 정리 · 판정). 한 실행에 브라우저 둘(엔진 · 녹화 · 실행 화면이 모두 «하나»를 전제)과 두 행 동시 실행(서로 맞출 길이 화면뿐)은 뺐다.
- **지갑을 실행마다 고르기** — `settings.wallet.secret`이 `{{ $params.이름 }}`이면 그 실행 입력(**고르기** 종류 · 보기가 글자 시크릿 이름들)의 값이 키 시크릿이다(core `walletSecretName`). 검문소: 입력이 있나 · 고르기인가 · 보기마다 글자 시크릿인가. 보기 밖 값은 입력 검사가 막고, 엔진도 이 워크플로우의 시크릿인지 다시 본다. 녹화는 녹화 입력(없으면 기본값)의 지갑으로. 화면: 지갑 설정의 키 시크릿 고르기에 «실행 입력 …으로 고르기».
  까닭: 토큰을 가진 쪽이 판매자라 역할이 실행마다 바뀐다 — 없으면 역할 워크플로우를 지갑마다 두 벌.
- **새로고침하며 기다리기** — «보일 때까지» · «사라질 때까지»에 `reloadEveryMs`(2초~10분). 간격마다 보고 아니면 다시 열고(load → 조용해질 때까지 5초까지) — 다 기다리는 시간은 동작의 시간 제한. 기록에 «새로고침 N번 만에». ★«사라질 때까지»는 안 그려진 화면에서도 맞으니 다시 연 뒤 그려지기를 먼저 기다린다.
- **MetaMask 승인 «적어도 N개»**(`atLeast` 1~10) — 끝 표시가 와도 그만큼 승인하기 전에는 믿지 않는다. 누른 단추가 처리 중 모양으로 바뀌면 «사라짐» 끝 표시가 지갑 요청 전에 맞아, 실행이 끝나며 요청이 버려졌다(QA 구매). 시간이 다 되면 «사이트가 지갑을 부르지 않았다».
- **체인 맞추기가 곧바로 거절되면 멈춘다** — RPC 없이 둔 체인을 MetaMask가 모르면(4902) 승인 창이 오지 않는데 45초를 기다렸다. 까닭(«RPC를 넣으면 먼저 더한다»)과 함께 곧바로 멈춘다.
- 예시: `examples/msu-qa` «MSU QA · 거래» — P2P(`trade-p2p` + 부품 다섯) · 지갑 키는 팀 공용 시크릿. **QA에서 NFT 아이템 · 캐릭터 둘 다 통과**(2026-10-27, 각 3분 남짓 · 실행마다 역할이 뒤바뀜).

## 48. 목록 — 이름이 아니라 주소로 묶기 (2026-10-27)

사용자: «워크플로우를 이름으로 분류하는 게 별로 좋지 않다 — 다른 방법?» 본 것(MSU QA 74개): 같은 분류가 **세 군데** — 이름 앞말(«Navigator · …») · 묶음(group) · Suite(«MSU QA · Navigator» 37개) — 거의 1:1. 사람이 셋을 손으로 맞춘다 · 이름이 길어진다 · 한 축만.

  - 목록(`GET /api/flows`)이 줄 때 맞춘다(`area` · `site`) — 초안에서 읽은 주소는 초안이 바뀔 때만. 규칙을 바꾸면 초안을 안 고쳐도 다시 묶인다.
- **직접 지정**은 틀린 것만 — 2단계의 `flow.group_name`이 그대로 «직접 지정한 화면»이 됐다(이기면 줄에 «직접 지정» 표 · 툴팁에 주소로는 무엇인지). 자동과 같은 직접 지정은 화면 규칙 창에서 한 번에 풀기(주소가 바뀔 때 따라가게).
- **묶어 보기**: 화면(기본) · Suite(들어 있는 Suite마다 — 여럿이면 여러 곳 · 없으면 «Suite에 없음») · 묶지 않음. 접은 것은 축마다 따로 기억.
- 화면 규칙 창: 줄마다 주소 앞부분 · 이름 · **맞는 수 미리 보기** · 제안(규칙에 안 맞은 것을 «호스트/첫 마디»로 모아 둘 이상) · 규칙이 없으면 목록 위에 한 번 «주소로 화면을 나눌 수 있습니다».
- 뺀 것(2단계에서): 줄을 묶음 머리로 끌어 놓기 · 묶음 이름 바꾸기 · «이름 앞말로 정리» 제안 — 모두 «사람이 분류를 관리한다»는 것이었다.
- `examples/msu-qa/import.ts`: 묶음 대신 화면 규칙 넷을 더한다(있는 규칙은 둔다).
★이름 앞말은 **데이터에서 떼지 않았다** — 목록은 묶음 머리와 같은 앞말을 떼어 보이지만(«이름 검색 → 상세»), 대시보드 · 실행 기록 · Suite처럼 섞여 보이는 곳에서는 앞말이 있어야 어느 서비스인지 안다. 새로 짓는 이름에 붙일지는 사람 몫.

## 49. 페이지를 파일로 모으기 — 행마다 반복 · 파일로 저장 (2026-10-27)

사용자: «confluence.nexon.com에 접속 → 사람이 로그인 → 좌측 트리 05. 팀 별 공간 > 08. 플랫폼개발 > [서비스파트] 아래 모든 페이지를 PDF로 → 저장». 형식은 PDF.
본 것: 파일 쓰기 노드는 글자(csv · jsonl · json · text)만 쓴다 · 페이지마다 도는 길은 «다른 워크플로우 실행»뿐인데 자식 실행은 새 브라우저라 로그인이 이어지지 않는다.
정한 것:
- **웹페이지 노드 «행마다 반복»**(`config.each { items, onError }`) — 행들마다 시작 · 동작을 한 번씩, 한 브라우저 · 한 로그인으로. 노드 안 어디서나 `$item`. 주소로 시작하면 행마다 그 주소로 · 앞 페이지에서 이어서면 머문 곳에서(주소에서 받기만 하는 수집). 출력 rows(그 행의 값 + 읽은 것 + ok · error) · succeeded · failed. 실행 기록의 단계에 «[3/120]».
- **«파일로 저장» 동작**(`save { source: url | page, url, path, output, skipExisting }`) — url: 그 주소를 **이 브라우저의 로그인(쿠키)으로** 받는다(화면은 옮기지 않는다 · 상대 주소 됨) · page: 지금 페이지를 PDF로(창 없는 브라우저만). 이 워크플로우의 폴더 아래 path(표현식)에 쓰고, 마디마다 파일 이름에 못 쓰는 글자를 바꾼다(180바이트까지 · 확장자는 남긴다).
  ★`.pdf`인데 «%PDF-»로 시작하지 않으면 쓰지 않고 멈춘다 — 로그인 풀림 · 권한 없음 화면(HTML)을 PDF 이름으로 남기지 않게. 로그인 화면으로 넘어갔으면 그 까닭으로. 이미 있으면 건너뛰기(끊긴 수집 이어 하기). 동작 시간 제한이 없으면 3분(큰 PDF 내보내기).
- 파일 다루기에 `writeBytes` — PC 워커는 base64로 서버에 맡긴다(파일은 늘 서버에 남는다).
- 예시 `examples/confluence/confluence-pdf.json` — 로그인(사람) → REST로 페이지 목록(CQL로 시작 페이지 · `/child/page` 재귀 — 트리를 화면에서 펼치지 않는다) → 목록 CSV → 페이지마다 PDF 내보내기 → 결과 CSV → 판정. 가짜 Confluence로 끝까지 확인 · 사내 위키는 사람이 로그인해 돌려 봐야 한다.

### 49-2. 사내 위키에서 돌려 고친 것 (2026-10-27)

- 시작 페이지 찾기 — 제목 검색(CQL `title=`)이 0개였다(실제 제목은 «[서비스 파트]» · 띄어쓰기). 제목 그대로 → 종류 무관 → 글자 검색 → **트리를 이름으로 내려가기**로 찾고, 제목은 공백 · 전각 괄호 · 대소문자를 무시하고 견준다. 499쪽.
- PDF 내보내기가 모든 쪽에서 **HTTP 403** — 매번 «다시 해 봅니다»까지 돌았다. «파일로 저장»: 거부(4xx) · PDF 아님 · 로그인 화면은 다시 해 보지 않는다(같은 답) · 실패 까닭에 서버가 말한 글(160자)을 붙인다 · 요청 머리(`headers` — 쿠키 · 인증 · host는 못 넣음) · 요청에 Referer(지금 페이지).
- 예시: 내보내기에 `X-Atlassian-Token: no-check` · 실행 입력 «받는 방법»(export · page) — page는 페이지를 열어 화면 그대로 찍는다(창 없는 브라우저).

## 50. 다시 실행 — 실행 머리 · 위 막대 · 여기서부터 다시 (2026-10-27)

사용자: «(실행 기록 화면) 다시 실행하려면 어떻게 해야 하는지 모르겠다». 본 것: 다시 실행 단추가 «워크플로우 결과»를 골랐을 때만 상세 칸 안에 작게 있었다(단계를 고르면 사라짐) · 위 막대에 실행이 없고 편집기 아래 막대에만 · 다시 하면 늘 처음부터 — 사람 로그인으로 시작하는 2분 43초짜리가 뒤쪽 한 단계 때문에 처음부터.

## 52. 압축(zip) 노드 (2026-10-27)

사용자: «zip 압축 기능을 가진 노드도» — Confluence에서 499쪽 PDF를 모은 뒤 한 번에 받고 싶다.
정한 것 — **새 노드 «압축(zip)»**(값과 파일):
- `from { scope, dir, include[] }` → `to { scope, dir, name }` · `ifExists: overwrite | fail`. 폴더 · 이름은 표현식(`묶음-{{ $params.day }}`) · .zip은 붙여 준다 · 포함 규칙은 glob(`**` 폴더 넘어 · `*` · `?` · 대소문자 무시 · 비우면 모두). 출력 file · count · bytes.
- 라이브러리 없이 zlib(deflateRaw · crc32)로 쓴다(engine zip.ts). 한 파일씩 읽어 흘려 쓴다 · 이름은 UTF-8 표시(한글) · 이미 압축된 것(PDF · 그림 · zip · 오피스)은 그대로 담는다 · 눌러서 더 커지면 그대로.
- **압축은 파일이 있는 곳에서** — FileOps.zip. PC 워커는 서버에 맡긴다(묶을 것을 PC로 가져오지 않는다 · 묶을 폴더는 읽을 수 있는 곳 · 결과는 쓸 수 있는 곳만).
- 결과 zip 자신 · 쓰다 만 것(.part)은 묶지 않는다 · .part에 쓰고 다 되면 바꾼다(실패하면 남기지 않는다). ZIP64는 쓰지 않는다 — 65,535개 · 4GB를 넘으면 까닭과 함께 멈춘다. 묶을 파일이 없으면 · 폴더가 없으면 멈춘다. 점검은 이 노드 앞에서 멈춘다(파일을 쓴다).
- 설정 화면에 «만든 zip»(내려받기) · 타일 «pdf (**/*.pdf) → 묶음.zip» · AI 설명서에도.
- ★편집 화면은 초안을 열 때 노드 설정의 빈 칸을 기본값으로 채운다(normalize) — 압축 노드를 빠뜨렸더니 API로 넣은 초안(include 없음)에서 화면이 하얗게 죽었다(e2e로 잡음).
